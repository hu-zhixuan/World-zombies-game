## M0：搬家和搭架子（一个 PR，不改玩法，不发版）

1. **旧代码搬进 `legacy/`**：`src/`、`build.js`、`test_suite.js`、`dist/`、`tools/e2e/`、`docs/code_architecture_index.md`。搬完要保证 `node legacy/build.js` 还能拼出旧版，作为随时可以打开对照的参考。
2. **新工程**：按 `architecture.md` 第 4、5 节建目录和配置。打包结果是 `dist/index.html` 一个文件。
3. **内容抽取**：按 `architecture.md` 第 8 节的表，把剧情和内容表原样抽成 `src/content/` 下的数据文件。文本一个字不改。抽完写一个测试核对条数（比如 `01d_story_dialogue.js` 里有 103 行带 `text:` 的对白，新数据里不能少）。
4. **规则层的空壳**：`RunState` 的类型定义、固定步长的 `step()`、带种子的随机数、指令和事件的类型。先能跑「一只僵尸从右走到左」。
5. **CI 和发版**：`ci.yml`、`release.yml` 换成 `npm ci` / `npm test` / `npm run build`；`tools/copy_to_android.js` 改成拷 `dist/index.html`。在手机尺寸浏览器里用 `file://` 打开确认不报错。
6. 更新 `CLAUDE.md` 里的命令和目录说明。

验收：`npm test` 通过；`npm run build` 出单个 HTML；真实浏览器 `file://` 打开零报错；旧版仍可从 `legacy/` 构建。

## M1：竖切片（关卡：作者认可画面才能往下走）

### 第一步：先出效果图，不写玩法

做 3 张静态效果图（可以是真实渲染出来的截图），手机横屏比例：

1. **战斗画面**：主角站在墙上，2～3 只僵尸逼近，一座塔，顶栏和右下角按键。
2. **三选一**：清场后的天赋选择。
3. **工坊面板**：一把武器、星级、升星按钮。

最好给战斗画面出 2 个不同调色板 / 素材风格的版本让作者挑。把图发给作者，问一句话：「这个样子行不行，哪张更对？」**得到回答之前不要往下做。**

这一步的目的：作者说「丑」是感受层面的，文字描述对不齐，只有看图才能对齐。越早对齐，白做的越少。

### 第二步：按选定的风格做成能玩的

范围（只做这些）：

- 一屏战场：墙、主角（走、跳、翻滚、开火）、游荡者和冲刺者两种僵尸、机枪塔。
- 第 1～3 天，每天清场后三选一（先放 6 个天赋就够）。
- 手机操作：左摇杆、右下角攻击 / 翻滚 / 换弹 / 换枪。瞄准沿用 v56.4 的设计：自动锁屏幕内、面朝方向优先的目标，脚下红圈；按住攻击键拖动改为手动瞄准，方向附近有僵尸会吸附；松手回自动。旧实现在 `legacy/src/js/02f_mobile_controls.js`，逻辑可以照搬，放进规则层。
- 2 把武器（手枪、冲锋枪）加升星：捡到同名武器升星，武器栏显示星级。
- 一个工坊面板：用来证明面板 / 按钮 / 卡片这套界面组件。
- `architecture.md` 第 3 节「手感」里列的全部反馈。

不做：食堂、据点、剧情演出、Boss、存档、其他武器和僵尸。

### 验收

- [ ] 数值测试：手枪 ★1 打第 1 天游荡者 ≤ 4 枪；击杀时间在 0.5～1.5 秒
- [ ] 机器人能自动打完第 1～3 天
- [ ] 真实触摸脚本走通：开局 → 打完第 1 天 → 三选一 → 开工坊 → 关工坊 → 第 2 天，全程不卡
- [ ] 手机尺寸截图：没有黑边；主角约占画面高度六分之一；没有 emoji；画布里没有文字
- [ ] 界面自动检查通过：没有行内样式，没有调色板以外的颜色
- [ ] 作为预览版发 APK（比如 `v57.0-preview1`，Release 标成 pre-release），请作者在手机上看

发给作者时只问三件事：**样子对不对、手感爽不爽、字看不看得清。**
